# /审听

## 任务

根据原文、ASR 转写和音频信息，发现内容差异和可定位的录音问题。

## 输入

- `/画本` 生成的结构化稿件或原始文本。
- 一个或多个音频文件。
- 带时间戳的 ASR 结果；如果没有，先调用 ASR 工具生成。
- 可选的响度、削波、噪声和静音分析结果。

## 执行规则

1. 优先按 `segment_id` 对齐原文和 ASR；没有 ID 时先按顺序和时间戳建立候选对应关系。
2. 区分 `omission`、`insertion`、`replacement`、`reorder`、`pronunciation`、`segmentation`、`noise`、`clipping`、`silence` 和 `cutoff`。
3. 每个问题必须包含音频时间码；无法定位时设置 `timecode_status: unavailable`，不能伪造时间。
4. 同时给出 `expected_text`、`heard_text`、`severity`、`confidence` 和建议动作。
5. 文本 diff 只能作为证据之一。涉及发音、语气和音质时，要明确标注“需要人工复听”。
6. 低置信度问题进入人工复核队列，不得自动判定为返工。
7. 输出必须符合 `schemas/review-issue.schema.json`。

## 输出

输出问题 JSON 数组，并按严重程度排序：`blocker`、`high`、`medium`、`low`。

每个问题至少包含：

- `issue_id`
- `segment_id`
- `issue_type`
- `severity`
- `confidence`
- `expected_text`
- `heard_text`
- `suggestion`

## 质量门槛

- 不能把没有 ASR 或没有音频分析的数据描述成已完成审听。
- 同一段的连续问题可以合并，但不能吞掉不同类型的错误。
- 需要返工的问题必须能被剪辑或配音人员快速定位。
